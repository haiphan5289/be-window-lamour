## PRD Summary

> API quản lý "Chứng từ bán hàng" (Sales Order) cho hệ thống Lamour Spa & Cosmetics — bán hàng cho
> khách, trừ tồn kho, tính thuế GTGT, hỗ trợ đặt cọc/khuyến mại/nhân bản đơn và báo cáo doanh số.

- **Goal:** Cung cấp CRUD + Confirm/Unconfirm + Duplicate + Report API cho chứng từ bán hàng, tự
  động trừ tồn kho khi ghi nhận và hoàn lại khi bỏ ghi/xóa.
- **User story:** As a Lamour cashier, I want to record a sale against a customer with correct VAT
  and stock deduction, so that inventory and revenue stay accurate in real time.
- **Acceptance criteria:**
  - [x] `GET /api/v1/sales-orders` trả danh sách, lọc theo khoảng ngày + tìm kiếm
  - [x] `GET /api/v1/sales-orders/{id}` trả chi tiết
  - [x] `POST /api/v1/sales-orders` tạo mới — `Normal`, trừ tồn kho ngay (two-pass)
  - [x] `PUT /api/v1/sales-orders/{id}` cập nhật
  - [x] `DELETE /api/v1/sales-orders/{id}` xóa
  - [x] `POST /api/v1/sales-orders/{id}/confirm` / `/unconfirm` — Ghi sổ/Bỏ ghi
  - [x] `POST /api/v1/sales-orders/{id}/duplicate` — nhân bản thành đơn mới, số chứng từ mới, trừ kho lại
  - [x] `GET /api/v1/sales-orders/next-code` — số chứng từ tiếp theo, 2 chuỗi độc lập BH/XK
  - [x] `GET /api/v1/sales-orders/report` + `/summary-report` — báo cáo bán hàng theo sản phẩm/NV/KH

## Business Rules

| Rule | Description |
|------|-------------|
| Số chứng từ | 2 tiền tố độc lập: `BH{5 digits}` (tạo trực tiếp từ "Bán hàng") / `XK{5 digits}` (từ "Xuất kho bán hàng") — xem `SalesOrderCodeSource` |
| Dòng hàng | **Không bắt buộc ≥1 dòng** (2026-08-25) — đơn có thể chỉ dùng để trừ cọc, `Lines[]` được phép rỗng ở BE (WPF tự chặn phía client) |
| Sản phẩm còn kinh doanh | `Product.IsActive == true`, ngược lại 400 |
| Kho hợp lệ | Bắt buộc trừ dòng khuyến mại hoặc `Product.IsDepositProduct` — các dòng này không cần `warehouse_id` |
| Đủ tồn kho | Kiểm tra two-pass: validate hết mọi dòng trước, chỉ trừ kho thật nếu KHÔNG có dòng nào thiếu tồn — gộp lỗi từng dòng vào 1 `DomainException` |
| Hàng khuyến mại (`IsPromotion`) | Đơn giá/CK/Thuế luôn ép về 0 bất kể client gửi gì |
| `IsAmountManual` | Cho phép user gõ tay `Amount` (bỏ qua công thức `Qty×UnitPrice×(1-CK%)`) — chặn `Amount < 0`; luôn `false` cho dòng khuyến mại dù client gửi `true` |
| Thuế | `TaxRate` tự tính từ `Product.VatRate` (`SalesOrderTaxCalculator`), `TaxAmount = Amount × TaxRate / 100` |
| Trạng thái | `Normal` (đã ghi sổ, đã trừ kho) ⇄ `Held`/`Draft` (chưa ghi sổ — 2 giá trị lịch sử tương đương) |
| Tạo mới ("Cất") | Luôn `Normal`, trừ tồn kho ngay (2026-09-11, đảo ngược quyết định "Cất ra Treo" trước đó) |
| Bỏ ghi (`Unconfirm`) | Chỉ cho phép từ `Normal`, hoàn tồn kho two-pass trước khi đổi trạng thái |
| Nhân bản (`Duplicate`) | Gọi lại **chính** `ICreateSalesOrderUseCase` (không copy entity thẳng) — số chứng từ mới qua `GetNextSalesOrderCodeUseCase(Direct)`, **trừ kho lại thật** (không phải chỉ nhân bản dữ liệu) |
| Override tên/địa chỉ KH | `CustomerNameOverride`/`CustomerAddressOverride` — hiển thị khác `Customer.Name`/`Address` thật cho riêng chứng từ này, không đổi record khách hàng |
| Tài khoản mặc định | `ReceivableAccount = "131"`, `RevenueAccount = "511"` |
| `[Authorize]` | **Đang bật** trên `SalesOrdersController` (khác `SalesReturnsController`, nơi đang tạm tắt) |
| DB Transaction | Create/Update/Delete/Confirm/Unconfirm dùng `IUnitOfWork.BeginAsync` → `CommitAsync`/`RollbackAsync` |

## Edge Cases & Error Handling

| Scenario | Expected Behavior | Handled? |
|----------|------------------|----------|
| Create with 0 lines | Allowed (deposit-only order) — no longer rejected since 2026-08-25 | ✅ |
| Product not found / inactive | 400 with product name in message | ✅ |
| Warehouse missing for a real stock line | 400 `"Vui lòng chọn Kho cho hàng hóa '...'."` | ✅ |
| Insufficient stock across multiple lines | All shortages collected into one `DomainException` (not fail-fast on the first) | ✅ |
| `IsAmountManual` with negative `Amount` | 400 `"Thành tiền dòng '...' không được âm."` | ✅ (covered by test) |
| `IsAmountManual` on a promotion line | Forced to `false`/`0` regardless of client input | ✅ (covered by test) |
| Unconfirm a non-`Normal` order | 400 `"Chứng từ chưa ở trạng thái đã ghi sổ, không thể bỏ ghi."` | ✅ |
| Duplicate a non-existent order | 404 via `NotFoundException` | ✅ |
| Duplicate — stock re-deduction fails (insufficient stock now) | Bubbles up the same `DomainException` as a fresh Create would | ✅ (inherits from reused UseCase) |
| Missing endpoint auth | 401 — `[Authorize]` is active on this controller | ✅ |
